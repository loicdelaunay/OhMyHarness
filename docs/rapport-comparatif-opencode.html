1. Résumé exécutif

OhMyHarness est aujourd'hui un client de chat multimodal très complet avec une couche d'outils réelle (sources, éditeur de fichiers, terminal, Git en lecture, navigateur intégré avec accès DOM, automatisation souris/clavier/captures, permissions persistantes). Il sait aussi piloter un serveur opencode local via HTTP et lui déléguer la boucle agentique.

Mais comparé à opencode, il lui manque tout le socle qui fait d'opencode une plateforme agentique extensible plutôt qu'une application fermée : protocole MCP, agents/sous-agents personnalisables, règles projet (AGENTS.md), commandes personnalisées, outils utilisateur, plugins/hooks, diagnostics LSP, recherche de code (glob/grep), application de patch avec diff, annulation/restauration de session, export/import, mode headless scriptable, OAuth fournisseurs, catalogue de modèles avec coûts, et configuration portable hors base SQLite.

2. Méthode et périmètre

Trois passes ont été effectuées, en lecture seule :

  1. Lecture ciblée des fichiers structurants : src/OhMyHarness.Core/Skills.cs, ChatEngine.cs, SourceAccess.cs, WorkspaceTools.cs, Storage.cs, ModelCatalog.cs, ContextWindow.cs, ConversationSession.cs, OpenCodeEngine.cs, src/OhMyHarness.Service/Tools.cs, HarnessService.cs, Generations.cs, Program.cs, src/OhMyHarness.App/UiText.cs, desktop/ui/app.js, README.md.
  2. Recherche textuelle sur src, desktop, tests, docs (hors obj, bin, dist, node_modules) des motifs : lsp, language server, mcp, modelcontextprotocol, todowrite, glob, grep, patch, undo, revert, share, plugin, AGENTS.md, formatter, models.dev, subagent, worktree, keybind, websocket.
  3. Comptage de lignes pour situer la taille du socle (≈ 1 940 lignes pour MainWindow.cs, 1 135 pour WorkspacePane.cs, 431 pour les tests, le reste des fichiers C# métier entre 20 et 330 lignes).
Périmètre de la comparaison. Les fonctionnalités attribuées à opencode reposent sur la connaissance publique de ce projet (sst/opencode) et n'ont pas pu être revérifiées en ligne : l'accès navigateur est désactivé dans cette session. Aucune affirmation sur opencode n'est utilisée pour trancher un détail d'implémentation d'OhMyHarness ; tous les constats côté OhMyHarness sont, eux, appuyés sur un fichier et une construction de code précise.

3. Ce que OhMyHarness fait déjà

Il faut le poser avant les manques, car plusieurs briques sont déjà au niveau d'opencode, voire au-delà.

Boucle d'outils native multi-tours

Jusqu'à 12 tours d'appels d'outils par envoi, journal visible, résultats persistés (src/OhMyHarness.Service/Generations.cs).

Permissions granulaires et révocables

Autoriser une fois / toujours / refuser, portées persistées, mode global Refuser-Demander-Accepter (Tools.cs, Storage.cs).

Navigateur intégré avec accès DOM

WebView2, inspect_dom, browser_mouse, browser_keyboard, aperçu local à origine dédiée et dossier de ressources autorisé.

Automatisation du bureau

Souris, clavier, captures multi-écrans avec curseur enregistré, restauration de la fenêtre active (WorkspacePane.cs, DesktopInput.cs).

Conversations parallèles

Plusieurs générations simultanées, y compris sur des projets différents, avec sémaphores dédiés outils/permissions.

Compaction de contexte automatique

Seuil 95 %, résumé persisté, conservation des tours récents (ContextWindow.cs, Compact()).

Intégration d'un serveur opencode

Démarrage automatique, sessions dédiées par conversation, pont de permissions, désactivation ciblée des outils opencode (OpenCodeEngine.cs, Generations.cs).

4. Moteur agent et extensibilité

C'est la famille de manques la plus lourde : OhMyHarness possède un ensemble fermé d'outils et un prompt système construit dans le code. Rien de tout cela n'est étendable sans recompiler.

G1 Serveurs MCP P0 M · 1-2 semaines

Constat. Aucune mention de MCP dans le code : la recherche de mcp et modelcontextprotocol renvoie 0 occurrence sur tout le périmètre analysé.

Impact. Impossible de brancher un serveur d'outils externe (base de données, Jira, Figma, Playwright, serveurs distants authentifiés). opencode en fait son principal mécanisme d'extension ; ici, chaque nouveau besoin d'outil implique une modification du C# et une nouvelle publication.

Piste. Un client MCP (stdio + HTTP/SSE) dans src/OhMyHarness.Core/, une entité McpServer dans Storage.cs + migration, l'agrégation des outils distants dans Definitions() de src/OhMyHarness.Service/Tools.cs, et la réutilisation du flux d'approbation existant (Approve()) pour chaque appel d'outil MCP.

G2 Règles projet AGENTS.md P0 S · 1-2 jours

Constat. 0 occurrence de AGENTS.md. Le prompt système est assemblé en dur par Skills.Prompt() (src/OhMyHarness.Core/Skills.cs) et PlatformSupport.SystemPrompt; aucune lecture d'un fichier d'instructions du dépôt.

Impact. Les conventions d'un projet (style, architecture, commandes de build) doivent être répétées à chaque session ou collées dans un template. C'est le levier de qualité le moins coûteux d'opencode, et il manque ici.

Piste. Découverte hiérarchique (AGENTS.md global utilisateur, puis racine du projet, puis sous-dossiers) injectée dans le prompt après Skills.Prompt(), affichée dans l'IHM pour que l'utilisateur voie ce qui est chargé. À combiner avec la commande /init qui génère le fichier.

G9 Commandes personnalisées P1 M · 3-5 jours

Constat. Le concept le plus proche est le template : PromptTemplate { Name, Content } (Storage.cs) édité par TemplateEditor.cs. Un template préremplit la zone de saisie (DefaultTemplates.WebApp).

Impact. Pas d'arguments ($ARGUMENTS), pas d'injection de sortie shell, pas de référence @fichier, pas de sélection d'agent/modèle par commande, donc pas de commandes réutilisables du type /revue chemin/ ou /test.

Piste. Étendre PromptTemplate (description, agent cible, modèle, arguments déclarés) et ajouter un résolveur de placeholders côté Generations.cs avant l'envoi.

G7 Sous-agents et délégation P1 M · 1-2 semaines

Constat. Une seule boucle, un seul rôle assistant. La liste d'outils ne contient aucun équivalent de task : les identifiants opencode task, glob, grep, todowrite n'apparaissent que dans la liste de désactivation (src/OhMyHarness.Core/OpenCodeEngine.cs, méthode DisabledToolsAsync).

Impact. Pas de séparation exploration / édition, pas de sous-agent spécialisé, pas de parallélisme intra-conversation : chaque tâche longue sature la fenêtre de contexte principale.

Piste. Ouvrir la notion d'agent (prompt, modèle, liste d'outils, permissions) et un outil task qui démarre un ConversationSession enfant dans src/OhMyHarness.Service/Generations.cs.

G8 Agents personnalisés P1 M · 1 semaine

Constat. Aucune entité « agent » dans Storage.cs (les entités sont Project, Chat, Message, Attachment, Provider, ExternalChatSession, AppState, PromptTemplate, PermissionGrant). Le comportement est global : EnabledSkills et ThinkingLevel dans AppState, donc identiques pour tous les projets.

Impact. Impossible d'avoir un agent « plan » en lecture seule et un agent « build » qui écrit, ni un agent par projet. C'est pourtant le principal garde-fou d'opencode.

Piste. Ajouter Agent (nom, prompt, outil autorisé, modèle, mode) + migration, et remplacer la lecture directe de State.EnabledSkills dans src/OhMyHarness.Service/Tools.cs par une résolution « agent → outils ».

G21 Plugins et hooks P2 L · 2-4 semaines

Constat. 0 occurrence de plugin. Aucun point d'extension entre l'appel du modèle et l'exécution d'un outil : dans src/OhMyHarness.Service/Generations.cs, l'exécution est en ligne (try { result = await Tool(...) }).

Impact. Pas de garde-fou utilisateur (bloquer rm -rf, masquer un secret, formater après écriture) sans modifier et recompiler l'application.

Piste. Points d'accroche avant/après outil, avant envoi de message, sur événement de session. Techniquement, un hôte de script (JS via ClearScript, ou Python via un sous-processus JSON-RPC comme celui de Program.cs) évite d'introduire un runtime lourd dans le binaire.

G22 Outils fournis par l'utilisateur P2 L · 2-3 semaines

Constat. Le catalogue d'outils est écrit à la main en deux endroits qui se recouvrent partiellement : ChatEngine.ToolDefinitions(sources, browser, writeSources) (src/OhMyHarness.Core/ChatEngine.cs) et HarnessService.Definitions() (src/OhMyHarness.Service/Tools.cs). Le tri se fait par un switch sur le nom dans Tool().

Impact. Aucun moyen d'ajouter un outil métier sans publier une nouvelle version de l'application.

Piste. Introduire un registre d'outils (ITool : nom, schéma JSON, skill requis, exécution, portée d'autorisation) et faire converger les deux fonctions Definitions vers ce registre — c'est aussi le prérequis de G1, G7, G21 et G23.

G23 Skills à chargement progressif P2 M · 4-6 jours

Constat. Un skill est un simple interrupteur : Skills.Enabled(selection, id) teste l'appartenance à une chaîne séparée par des virgules (src/OhMyHarness.Core/Skills.cs), et toutes les instructions des skills actifs sont concaténées dans le prompt système.

Impact. Chaque skill actif consomme des tokens à chaque appel, même inutilisé ; impossible d'en installer beaucoup.

Piste. Un outil skill qui charge le contenu d'un dossier de skill à la demande, avec seulement les métadonnées (nom + description) dans le prompt.

5. Outils de code et qualité

G3 Recherche de code glob / grep P0 S · 2-3 jours

Constat. La surface d'exploration se limite à list_sources et read_source. SourceAccess n'expose que List(), ReadAsync(), WriteAsync(), ModifyAsync() (src/OhMyHarness.Core/SourceAccess.cs).

Impact. Sur un dépôt réel, l'agent doit deviner les chemins ou parcourir dossier par dossier : coût en tours d'outils et en tokens très élevé, avec une fenêtre de 12 tours seulement.

Piste. search_sources(pattern, glob?) renvoyant les correspondances avec numéros de ligne, en réutilisant le filtrage déjà écrit (Excluded, ReparsePoint, Take(300)) pour rester cohérent avec les exclusions de secrets.

G4 Patch multi-fichiers et diff avant application P0 M · 1-2 semaines

Constat. L'édition se fait par write_source (réécriture intégrale) ou edit_source (remplacement d'une seule occurrence, via current.IndexOf(oldText, StringComparison.Ordinal) dans ModifyAsync). Aucun diff n'est calculé ni montré avant écriture ; aucun mode multi-fichiers en un seul appel.

Impact. Risque d'erreur réel : si old_text apparaît plusieurs fois, c'est la première occurrence qui est modifiée, ce qui peut corrompre silencieusement un fichier. L'utilisateur approuve en outre un texte à remplacer sans voir le résultat final.

Piste. Un outil patch (format *** Update File ou diff unifié) appliqué de façon transactionnelle, avec rendu du diff dans le popup d'autorisation existant et refus si l'ancrage est ambigu.

G11 Écriture atomique et sauvegardes P1 S · 1-2 jours

Constat. WriteAsync et ModifyAsync écrivent directement (File.WriteAllTextAsync(full, content, ct)) sans fichier temporaire ni renommage, sans conservation de l'original, et sans verrou contre une écriture concurrente de l'éditeur de l'utilisateur.

Impact. Une interruption pendant l'écriture peut tronquer un fichier source ; aucune marche arrière n'existe (voir G5).

Piste. Écriture temporaire + File.Move(temp, cible, overwrite: true), copie de sauvegarde horodatée, et refus d'écrire si le fichier a changé depuis la dernière lecture par l'IA.

G10 Diagnostics LSP P1 L · 2-4 semaines

Constat. 0 occurrence de lsp et de language server ; aucun client LSP dans les trois projets C#.

Impact. L'agent ne sait pas qu'il vient de casser la compilation : c'est à l'utilisateur de signaler l'erreur, ce qui coûte un aller-retour complet par itération.

Piste. Client LSP minimal (initialisation, didOpen/didChange, collecte des publishDiagnostics) alimenté après chaque écriture, avec les erreurs du fichier touché renvoyées en fin de tour. Les serveurs détectables par extension peuvent être déclarés en configuration (voir G6).

G24 Formateurs automatiques P2 S · 2-3 jours

Constat. 0 occurrence de formatter. Le terminal est disponible (WorkspaceTools.ShellAsync) mais rien n'est déclenché automatiquement après une écriture.

Impact. Les diffs de l'IA ne respectent pas le format du projet ; le bruit de formatage pollue les relectures.

Piste. Exécuter le formateur du projet (Prettier, dotnet format, gofmt…) après chaque écriture réussie, avec le même mécanisme de timeout de 60 s que WorkspaceTools.cs.

G25 Liste de tâches (todo) P2 S · 2-3 jours

Constat. Aucun outil de planification persistée ; le skill planning (Skills.cs) n'injecte qu'une instruction textuelle. todowrite n'apparaît que dans la liste de désactivation d'OpenCodeEngine.cs.

Impact. Sur une tâche de plus de 12 tours, la limite est atteinte (for (int round = 0; round < 12; round++) dans Generations.cs) sans état intermédiaire visible pour reprendre.

Piste. Entité Todo par conversation + panneau dédié à côté du panneau Outils.

G27 Lecture d'images par l'outil de lecture P2 S · 1-2 jours

Constat. ReadAsync refuse tout ce qui n'est pas dans la liste blanche d'extensions textuelles (SourceAccess.Extensions) et tout fichier de plus de 128 Ko.

Impact. L'agent ne peut pas lire une capture d'écran, un diagramme ou une maquette déposée dans le dépôt, alors que le pipeline multimodal existe déjà (le résultat d'outil joint une image : ToolResult(string Text, Attachment? Image) dans Tools.cs).

Piste. Brancher read_source sur le chemin image existant, sous réserve de Provider.SupportsImages.

6. Sessions et cycle de vie

G5 Annulation et restauration P0 M · 1 semaine

Constat. 0 occurrence de undo et de revert. L'intégration Git est strictement en lecture : GitChangesAsync n'appelle que status, diff et diff --cached (src/OhMyHarness.Core/WorkspaceTools.cs). Aucun snapshot de dépôt (les 46 occurrences de « snapshot » concernent le curseur de souris et les captures d'écran).

Impact. Après une série d'écritures de l'IA, revenir en arrière demande un git checkout manuel, et rien ne relie un état de fichiers à un tour de conversation.

Piste. Snapshot avant le premier outil d'écriture d'un tour (arbre Git temporaire ou copie incrémentale), puis un point d'entrée « Revenir à ce message » dans l'IHM.

G12 Reprise, régénération, édition de message P1 M · 4-6 jours

Constat. L'historique est filtré sur State == "complete" (History() dans Generations.cs) : une réponse interrompue est conservée en base, affichée avec la mention « Réponse interrompue », mais jamais renvoyée au modèle. Il n'existe ni « continuer », ni « régénérer », ni « modifier ce message ».

Impact. Une coupure réseau ou un arrêt volontaire oblige à réécrire la demande complète, en perdant le raisonnement déjà produit et facturé.

Piste. Bouton de reprise qui remet le message partiel dans le fil, et suppression/branche à partir d'un message donné.

G14 Export, import, partage, fork P1 M · 4-6 jours

Constat. Le protocole du service est un JSON-RPC sur entrée/sortie standard (src/OhMyHarness.Service/Program.cs, ligne à ligne sur Console.In.ReadLineAsync) : il n'expose ni export de session, ni import, ni lien de partage. Les conversations vivent uniquement dans database.sqlite.

Impact. Impossible de transmettre une session à un collègue, de l'archiver, de la rejouer comme test de non-régression d'agent, ni de la bifurquer pour explorer deux pistes.

Piste. Export JSON/JSONL d'une conversation (messages, outil, métadonnées) et import inverse, sur le même modèle que history et snapshot déjà présents dans Dispatch.

G15 Compaction manuelle et pilotage du contexte P1 S · 1-2 jours

Constat. La compaction est uniquement automatique au-delà de 95 % (ContextWindow.ShouldCompact). La cible de 60 % est déclarée (CompactTarget) mais jamais utilisée dans Generations.cs. Aucune commande utilisateur, aucune estimation affichée du coût d'un résumé.

Impact. L'utilisateur subit la compaction au pire moment et ne peut pas anticiper (« je résume maintenant, avant d'attaquer la grosse tâche »).

Piste. Commande de compaction déclenchée à la demande, plus affichage du niveau de remplissage courant (la valeur limit est déjà envoyée à l'IHM dans l'événement stream).

G13 File d'attente et pilotage pendant une génération P1 S · 2-3 jours

Constat. Le bouton d'envoi est désactivé tant que la conversation tourne : $('send').disabled = !chatId || !providerId || running.has(chatId) (desktop/ui/app.js, updateControls()), et le service refuse un second envoi sur la même conversation (if (!runs.TryAdd(chat.Id, run)) throw dans Generations.cs).

Impact. Impossible de corriger le cap en cours de route (« en fait, pas ce dossier ») ni de préparer la demande suivante : il faut arrêter et perdre la génération en cours.

Piste. Autoriser la saisie et l'empilement du message ; l'appliquer soit après la fin du tour, soit en interrompant proprement (le mécanisme Cancellation et l'abandon d'OpenCode existent déjà).

7. Fournisseurs, modèles et coûts

G16 Authentification OAuth et abonnements P1 L · 2-3 semaines

Constat. Le seul mode d'authentification est la clé API / le mot de passe, stocké chiffré : Provider.ProtectedKey + KeyVault DPAPI sur Windows, Keychain via l'hôte sur macOS (src/OhMyHarness.Core/Storage.cs, src/OhMyHarness.Service/HarnessService.cs).

Impact. Pas d'accès aux offres par abonnement (Claude Pro/Max, GitHub Copilot, Google), qui représentent souvent l'essentiel du quota réel des utilisateurs. Le partage de clé par compte devient la seule option.

Piste. Flux OAuth par fournisseur (ouvrir le navigateur, écouter le retour de redirection, rafraîchir le jeton) avec les mêmes garanties de stockage chiffré que les clés actuelles, et une entrée « renouvellement » dans ProviderEditor.

G17 Catalogue de modèles et capacités P1 M · 1 semaine

Constat. src/OhMyHarness.Core/ModelCatalog.cs est une liste figée (30 modèles DeepSeek, 10 OpenAI, 12 génériques, 6 opencode) et GetDefaultContextLimit devine la fenêtre par sous-chaîne du nom (if (m.Contains("gpt-4o")) return 128_000;). Le README assume que la limite est une configuration utilisateur et non une détection. Aucune mention de models.dev.

Impact. Chaque nouveau modèle exige une recompilation, et la fenêtre de contexte — dont dépend directement la compaction et donc la qualité des longues sessions — peut être fausse.

Piste. Charger un catalogue distant (avec cache local et repli hors ligne), l'exposer dans provider.models qui sait déjà interroger /models, et préremplir ContextLimit et SupportsImages à la sélection.

G18 Coût monétaire par session P1 S · 2-3 jours

Constat. Le suivi est en tokens et tokens/s : Message { InputTokens, OutputTokens, Seconds }, GenerationSpeedTracker, SpeedStats (src/OhMyHarness.Core/ChatEngine.cs). Aucun prix n'est stocké ni affiché, et les tarifs ne sont pas dans le catalogue de modèles.

Impact. Impossible de savoir ce qu'a coûté une session ou une compaction automatique — alors qu'une compaction déclenche un appel de modèle supplémentaire payant, fait notable et invisible (voir Compact() dans Generations.cs).

Piste. Ajouter inputCost/outputCost au catalogue (G17) et un compteur cumulé par conversation, affiché à côté du débit déjà présent.

8. Interfaces, API et distribution

G6 Configuration portable et versionnable P0 S · 2-3 jours

Constat. Toute la configuration vit dans SQLite via EF Core et des migrations versionnées (Storage.cs, dossier src/OhMyHarness.Core/Migrations). Aucun équivalent d'opencode.json (~0 occurrence de keybind, theme).

Impact. On ne peut pas committer la configuration d'un projet, la partager, ni la relire. Une équipe ne peut pas normaliser les fournisseurs, agents, commandes et permissions d'un dépôt.

Piste. Fichier ohmyharness.json (schéma + validation) au niveau utilisateur et au niveau projet, fusionné au-dessus des valeurs SQLite, avec les secrets exclus du fichier.

G20 CLI headless et API HTTP P1 L · 2-3 semaines

Constat. Le service est un side-car en JSON-RPC sur stdin/stdout, démarré par l'hôte (Program.cs, argument --database obligatoire). Aucun écouteur réseau, aucune ligne de commande d'agent, aucun SDK : le dispatch interne (Dispatch(method, JsonObject, ct) dans HarnessService.cs) contient déjà tout le métier, mais n'est joignable que par le processus parent.

Impact. Pas d'usage en intégration continue (« corrige les tests et ouvre une PR »), pas de scénario reproductible, pas d'intégration par un autre outil. C'est le principal écart de plateforme avec opencode.

Piste. Transporter le même protocole sur un socket local (HTTP + authentification par jeton, comme le mode serveur d'opencode) et ajouter un mode « run » non interactif avec code de sortie exploitable en CI.

G26 TUI, thèmes, raccourcis, mise à jour automatique P2 L · 2-4 semaines

Constat. 0 occurrence de keybind, theme ; les libellés sont figés dans le code de l'IHM (src/OhMyHarness.App/MainWindow.cs, 1 940 lignes) et traduits par un dictionnaire statique (voir §9). Aucun mécanisme de mise à jour.

Impact. Pas d'usage sur un serveur distant sans interface graphique, pas de personnalisation, et chaque correctif exige de republier et de faire réinstaller l'application.

Piste. À traiter après G20 : une fois l'API réseau disponible, une interface texte peut s'y brancher sans réécrire le métier.

9. Permissions et confinement

G19 Permissions par motif P1 M · 1 semaine

Constat. Une autorisation est stockée comme une chaîne de portée unique (PermissionGrant { Scope, Name, Details }, index unique sur Scope) et testée par égalité exacte : await db.PermissionGrants.AnyAsync(x => x.Scope == scope) dans Approve() (src/OhMyHarness.Service/Tools.cs). Les portées sont construites par concaténation : "terminal|" + directory, "preview|" + folder, "opencode|{id}|{directory}|{action}|…".

Impact. Le choix est binaire par dossier : autoriser git status dans un projet autorise aussi rm -rf dans ce projet. Aucune règle du type « autoriser git *, refuser rm * », et pas de granularité par outil ou par agent.

Piste. Table de règles (outil, motif, décision) évaluée avant le flux actuel, avec les motifs en tête de liste prioritaires ; l'IHM des Autorisations (SettingsWindow.cs) affiche déjà la liste, elle peut être étendue.

G28 Confinement du terminal P1 L · 2-3 semaines

Constat. Le terminal exécute powershell.exe (ou zsh/sh) avec les droits de l'utilisateur, sans restriction réseau ni système de fichiers (WorkspaceTools.PowerShellAsync / ExecuteAsync). Le README le reconnaît : « Ces restrictions ne constituent pas un sandbox pour les commandes terminal autorisées. »

Impact. Le modèle de permissions protège contre une erreur, pas contre une commande hostile ou un fichier source piégé (une instruction cachée dans un fichier lu peut proposer une commande destructrice — attaque par injection de prompt, que le prompt système tente d'atténuer sans pouvoir l'empêcher).

Piste. Exécution dans une tâche restreinte Windows (AppContainer/Job Object) avec liste blanche de chemins et coupure réseau par défaut, au moins pour les commandes proposées par l'IA.

10. Fragilités observées dans le code

Ces points ne sont pas des écarts avec opencode, mais des dettes qui gêneront les évolutions ci-dessus.

Traduction par correspondance inverse de chaîne

src/OhMyHarness.App/UiText.cs :

var key = English.ContainsKey(text) ? text : English.FirstOrDefault(x => x.Value == text).Key ?? text;
return Language == "en" ? English.GetValueOrDefault(key, text) : key;

La clé du dictionnaire est la chaîne française elle-même, et la traduction inverse se fait en comparant les valeurs. Conséquences : une chaîne non répertoriée reste en français en mode anglais, une virgule typographique ou une espace insécable modifiée dans l'IHM casse silencieusement la traduction, et deux entrées de même valeur sont indiscernables. Le dictionnaire compte environ 190 entrées pour une interface de près de 2 000 lignes.

Piste. Clés stables (ui.settings.title) et ressources .resw ou fichiers JSON par langue, avec un test qui échoue quand une clé manque.

Prompt et descriptions d'outils non localisés

Les descriptions d'outils de ChatEngine.ToolDefinitions (src/OhMyHarness.Core/ChatEngine.cs) sont en français uniquement, tandis que celles de HarnessService.Definitions() (Tools.cs) sont en anglais. Le prompt système mélange également les deux : en mode anglais, le renvoi d'aide cite les libellés français — « inform them to open the 'Navigateur' panel and enable the 'Accès IA au navigateur' switch » (Skills.cs) — alors que l'interface affiche alors Browser et AI browser access (UiText.cs).

Impact. L'agent donne des instructions que l'utilisateur anglophone ne peut pas retrouver à l'écran.

Limites codées en dur

  • 12 tours d'outils par envoi : for (int round = 0; round < 12; round++) (Generations.cs), avec un message demandant « continue ».
  • Délai de génération : CancellationTokenSource(TimeSpan.FromMinutes(provider.IsOpenCode ? 30 : 10)) (ConversationSession.cs) — une tâche agentique longue est coupée à 10 minutes, sans possibilité de prolonger.
  • Fenêtre de contexte : 128 000 par défaut, plafonnée par Math.Clamp(..., 1024, 10_000_000) (HarnessService.cs).
  • Lecture : 128 Ko par fichier, 300 entrées par listage, 100 000 caractères de sortie terminal, 8 Mo par image.

Impact. Ces valeurs devraient devenir des réglages (elles sont aujourd'hui des constantes), sinon les cas d'usage longs resteront impossibles.

Tolérance des entrées de Skills.Enabled

selection.Split(',', StringSplitOptions.RemoveEmptyEntries) sans TrimEntries, puis Contains(id, StringComparer.Ordinal) (Skills.cs) : une espace après une virgule suffit à désactiver un skill sans message d'erreur. Le filtrage à l'écriture (state.EnabledSkills = string.Join(',', ...) dans HarnessService.cs) ne supprime pas non plus les espaces.

Deux définitions d'outils à maintenir en parallèle

ChatEngine.ToolDefinitions et HarnessService.Definitions déclarent tous deux les outils, avec des types de paramètres gérés différemment : la première force "type":"string" pour tous les paramètres, la seconde accepte un type par propriété (utile pour desktop_mouse qui attend des number/integer). Le prompt système est encore ailleurs (Skills.Prompt).

Impact. Toute évolution d'outil doit être répercutée en trois endroits — ce qui pénalise directement G1, G4, G7, G22 et G24.

12. Limites de cette analyse

  • Analyse statique : aucun code n'a été exécuté, aucune application lancée pour ce rapport. Un comportement peut différer de la lecture du code.
  • Le dossier desktop/dist, obj et bin ont été exclus des recherches ; ils contiennent des artefacts générés (dont un fichier de licences de 297 000 lignes qui faussait tous les comptages).
  • Les fonctionnalités d'opencode sont décrites de mémoire et non vérifiées en ligne (accès navigateur désactivé dans cette session). Aucun identifiant de version n'est cité volontairement : les écarts listés sont des familles fonctionnelles, pas une comparaison à une version précise.
  • Les efforts indiqués sont des ordres de grandeur pour un développeur familier du dépôt, hors tests d'intégration multi-plateformes (Windows et macOS sont tous deux supportés, ce qui double la charge pour le terminal, les permissions système et les entrées natives).
  • Le fichier docs/macos.md, les gabarits GitHub et rapport-diagnostic-outils-ia.md n'ont pas été dépouillés ligne à ligne ; une partie des écarts y est peut-être déjà planifiée ou assumée.
